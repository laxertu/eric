Queue patterns#

Messaging patterns built on queues and handlers.

class DeadLetter#

Bases: MessageContract

A message that could not be delivered or processed, plus where it was going and why it failed.

It wraps the original message: id, type and payload are the original ones, and message keeps its class, e.g. a SignedMessage with its sender.

To redeliver it: channel.dispatch(dead_letter.connection_id, dead_letter.message).

Parameters:

  • connection_id (str) – Id of the connection the message was meant for.

  • message (MessageContract) – The original message.

  • error (str) – Description of the error, e.g. repr() of the exception.

class DeadLetterHandler#

Bases: QueuingErrorHandler, ListenerErrorHandler

Dead Letter pattern: messages that could not be delivered or processed are pushed to a dead letter queue, wrapped in a DeadLetter.

A message is dead-lettered when:

  • pushing it to a listener’s queue fails, see handle_push_error();

  • the listener’s on_message() fails, see handle_on_message_error().

Pop errors are not dead-lettered: no message is available when they occur.

Register the same instance for both kinds of errors:

dead_letters = DeadLetterHandler()
channel.add_queuing_error_handler(dead_letters)
channel.add_listener_error_handler(dead_letters)

or, for every channel of a repository, with queuing_error_handler() and listener_error_handler().

If pushing to the dead letter queue fails too, the error is logged and the message is lost: the handler never raises, so the original error is the one the channel re-raises or logs.

Parameters:

queue (Queue) – The dead letter queue. Defaults to an InMemoryQueue.

class ReliableQueue#

Bases: Queue[MessageContract, ReliableMessage]

Reliable Queue pattern: a popped message isn’t removed, it is moved to an in-flight storage until it is acknowledged.

  • pop() and wait_pop() return a ReliableMessage;

  • ack() removes it for good, once it has been handled, e.g. when the client confirms it got it;

  • nack() puts it back in the queue at once;

  • messages not acknowledged within visibility_timeout seconds are put back in the queue by requeue_expired(), that pop() and wait_pop() call before popping.

Delivery is at least once: a message acknowledged after its visibility timeout may already have been put back, and is delivered again. Re-queued messages go to the end of the queue.

It wraps another queue, that keeps the messages waiting to be popped, and a KvStorage for in-flight messages. With durable ones, unacknowledged messages survive a restart. It can be pickled if both can, so it can be persisted by a queue repository.

Parameters:

  • queue (Queue) – Queue of messages waiting to be popped. Defaults to an InMemoryQueue.

  • visibility_timeout (float | None) – Seconds a popped message can stay unacknowledged. None: until nack().

  • in_flight (KvStorage) – Storage of popped messages not yet acknowledged. Defaults to an InMemoryStorage.

async wait_pop(timeout)#

Waits for the next message without blocking the event loop.

The default implementation runs pop() with timeout in a worker thread, so it takes one thread per waiting call. Override it with a native async wait when possible.

Parameters:

timeout (float) – Seconds to wait for a message.

Return type:

ReliableMessage

Raises a NoMessagesException if no message arrives within timeout.
